# Quill

一个浏览器扩展 + 网页工作台，用来把网申填写这件事做得体面一点。

它读取你正在填写的网申页面，对照你上传的简历给出填写方案；遇到资料里没有的字段，它会安静地记住你自己填的答案。
所有数据都保存在本机浏览器里，不连接任何服务器。

---

## 它解决什么

网申表格有三个反复出现的痛点：

1. **字段识别**。表单里的标签五花八门——「手机号码 / 联系电话 / Mobile Phone」说的是同一个东西，
   而且大量中文 ATS 的标签和输入框在 DOM 里根本没有任何关联。
2. **填写依据**。「性别」该填什么显然，「期望薪资」呢？「是否有亲属在本单位任职」呢？
   填错一个字段的代价可能是整份申请被判无效。
3. **你填过的内容下次还要重填**。「政治面貌」「紧急联系人电话」这类信息简历里往往没有，
   但你每次都填同一个值。

Quill 分别处理这三件事：**识别 → 依据你的资料思考 → 从你的操作中学习**。

---

## 三个能力

### 1. 字段识别与填写

扩展在页面上枚举所有可填写控件，从六个来源按可靠度依次恢复标签：

```
label[for] → aria-label/labelledby → 表格前导单元格 → 定义列表 → 前序文本 → placeholder → name/id
```

然后把标签、提示、分组标题、`autocomplete`、属性名一起送进分类器，映射到约 120 个规范字段键
（`contact.phone`、`education.endDate`、`essay.whyCompany` …）。

填写时会识别控件类型并用对应的写入方式：原生 `<select>`、React/Vue 受控组件（走 prototype setter
绕开框架的 value 描述符）、antd / element-ui / react-select 自定义下拉（需要真实指针事件序列）、
单选组、多选组、日期控件、富文本。写完一定回读校验。

### 2. 填写策略

每个字段都按固定的信任层级求解候选值：

```
该网站的历史记忆 → 已确认的记忆 → 学到的记忆 → 简历资料 → 由简历整理生成 → 公开的默认值
```

每一条候选值都带**来源说明**和**简历原文引用**，显示在面板里。层级之外还能看到「为什么」——
这是产品的核心，而不是装饰：一个不能解释自己为什么这么填的自动填写工具不值得信任。

超过 400 字的开放题（自我介绍、职业规划）会从你的真实经历里组装一段草稿，并标注「由简历内容整理生成」。
资料不足时它返回空，而不是编一段听起来合理的话。

### 3. 自主学习

资料库里没有的字段，你自己填了之后会被记住：

- 只学习**扩展没有填过**的字段（按值比对，不依赖时序，避免把自己写进去的内容当成用户输入）
- 验证码、协议勾选框、密码字段永不记忆
- 敏感字段（身份证号、手机号、地址）照常存储，但在界面上默认打码
- 同一字段再次出现时，记住的值优先于简历

工作台里有完整的「记忆库」页面，可以逐条核对、修改、删除，或全部清空。

## 网页工作台

浏览器图标弹窗只负责当前页面，完整功能在工作台：

| 视图 | 做什么 |
|------|--------|
| **总览** | 「我现在该做什么」——按真实工作顺序排列的下一步 |
| **简历** | 上传 PDF/DOCX/TXT，逐字段核对解析结果并就地修改 |
| **岗位** | 粘贴岗位描述，提取要求与权重，生成针对性简历建议、求职信、面试准备 |
| **台账** | 每次投递的记录、阶段、下一步行动、面试前回顾当时提交了什么 |
| **记忆** | 查看、编辑、删除扩展学到的内容 |
| **设置** | 行为偏好、外观、导出/导入/删除全部数据 |

岗位润色遵循一条硬规则：**重排、强调、改写，绝不编造**。
每条改写后的经历都保留原文与改写理由，因为一份面试时讲不出来的简历比没润色过更糟。
缺口分析会如实告诉你哪些要求简历没有覆盖，而不是用漂亮话掩盖。

## 开发

```bash
npm install

npm run typecheck      # 三个包的 TypeScript 检查
npm test               # 108 个单元测试（解析、分类、策略、学习、润色、台账）
npm run build:extension  # 构建扩展（含工作台页面）→ extension/dist
npm run build:web        # 构建独立网页版 → web/dist

npm run browsers       # 下载 Chrome for Testing（e2e 需要）
npm run test:e2e       # 真实浏览器端到端验证（45 项断言）
npm run test:all       # 上面全部跑一遍
```

### 在浏览器里加载

1. `npm run build:extension`
2. Chrome 打开 `chrome://extensions`，开启「开发者模式」
3. 「加载已解压的扩展程序」，选择 `extension/dist`
4. 点扩展图标 → 打开工作台 → 上传简历

### 为什么需要 Chrome for Testing

正式版 Google Chrome 会静默忽略 `--load-extension`（日志里写
`is not allowed in Google Chrome, ignoring`），并且阻止自动化标签页访问 `chrome-extension://`。
端到端测试因此必须用 Chrome for Testing，`npm run browsers` 会下载到 `chrome/`。

## 结构

```
packages/core       与环境无关的核心引擎（无 DOM、无 chrome API）
  text.ts           归一化、相似度、日期解析
  types.ts          领域模型
  fields/           字段词典 + 分类器
  resume/           简历分段与解析
  strategy/         取值求解、选项匹配、长文组装、学习
  tailor/           岗位分析与简历润色
  ledger/           投递台账的纯函数

packages/design     设计令牌与基础层（两个界面共用）

extension/          MV3 扩展
  src/content/      扫描、标签恢复、填写、学习监听
  src/ui/           面板、弹窗、设置、首次运行
  src/shared/       消息协议、存储
  build.mjs         打包脚本

web/                工作台（React + Vite）
  src/data/         存储适配器（扩展内 / localStorage 双后端）
  src/views/        六个视图

test/               单元测试 + 端到端 + 真实表单样本
scripts/            构建、打包、测试、图标生成
```

核心引擎刻意不依赖 DOM 或 `chrome.*`，所以同一份逻辑同时跑在
service worker、内容脚本和网页工作台里，单元测试也不需要浏览器。

## 设计

苹果式材质语言，从 apple.com 实际发布的 CSS 里取值而非凭印象：

| 令牌 | 值 | 来源 |
|------|-----|------|
| 导航玻璃 | `saturate(180%) blur(20px)` | apple.com globalheader.css |
| 导航底色 | `rgba(250,250,252,.8)` / `rgba(22,22,23,.8)` | 同上 |
| 主色 | `#0071e3` / `#0077ed` / `#006edb` | `--sk-button-background` |
| 字体栈 | SF Pro Display/Text → PingFang SC → 微软雅黑 | apple.com font-family |
| 缓动 | `cubic-bezier(0.66,0,1,1)` 系 | product overview CSS |
| 描边 | `0.5px` 发丝线 | 同上 |

其余是自定的：9 级字号、4px 间距网格、圆角阶梯、语义色、阴影配方。
暗色不是反转——它按 Apple 的做法用表面明度建立层次，并降低强调色饱和度。

面板用 shadow root + `all: initial` 隔离，页面样式进不来，面板样式也出不去。
窄屏下面板变成底部抽屉，工作台的侧栏变成底部标签栏。

## 隐私

- 不连接任何服务器。简历、记忆、台账全部在 `chrome.storage.local` / `localStorage`
- 简历文件不保存原文件，只保留提取出的文字（`storage.local` 约 10 MB 上限）
- 只有你点击「填写」时才会写入页面
- 验证码与协议勾选框永不自动填充
- 设置页可以一键导出 JSON 备份，或彻底删除

唯一离开设备的情况是你主动点击「导出」。
