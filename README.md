# Quill

一个浏览器扩展 + 网页工作台，用来把网申填写这件事做得体面一点。

它读取你正在填写的网申页面，对照你上传的简历给出填写方案；遇到资料里没有的字段，它会安静地记住你自己填的答案。
资料保存在本机浏览器里。简历模型识别默认关闭；只有你主动开启并确认后，简历文字才会发到识别服务器。服务器只做转写与结构化，
不保存文件或结果，也可以随时在设置里完全关闭。

---

## 它解决什么

网申表格有三个反复出现的痛点：

1. **字段识别**。表单里的标签五花八门——「手机号码 / 联系电话 / Mobile Phone」说的是同一个东西，
   而且大量中文 ATS 的标签和输入框在 DOM 里根本没有任何关联。
2. **填写依据**。「性别」该填什么显然，「期望薪资」呢？「是否有亲属在本单位任职」呢？
   填错一个字段的代价可能是整份申请被判无效。
3. **你填过的内容下次还要重填**。「政治面貌」「紧急联系人电话」这类信息简历里往往没有，
   但你每次都填同一个值。

Quill 分别处理这三件事：**识别 → 依据你的资料思考 → 从你的操作中学习**。

## 三个能力

### 1. 字段识别与填写

扩展在页面上枚举所有可填写控件，从六个来源按可靠度依次恢复标签：

```
label[for] → aria-label/labelledby → 表格前导单元格 → 定义列表 → 前序文本 → placeholder → name/id
```

然后把标签、提示、分组标题、`autocomplete`、属性名一起送进分类器，映射到约 120 个规范字段键
（`contact.phone`、`education.endDate`、`essay.whyCompany` …）。

填写时会识别控件类型并用对应的写入方式：原生 `<select>`、React/Vue 受控组件（走 prototype setter
绕开框架的 value 描述符）、antd / element-ui / react-select 自定义下拉（需要真实指针事件序列）、
单选组、多选组、日期控件、富文本。写完一定回读校验。

不少 ATS 把教育经历、工作经历、项目经历渲染成**完全空白的分组**，只留一个「添加」按钮。
扫描阶段只会提示「这几栏还是空的，点填写时会先自动添加」，不会碰页面；只有你点「填写」后，
扩展才按简历里的记录条数点击「添加」，等新行渲染出来，重新识别，再逐字段填写。
没有对应记录的栏目不会被撑出一堆空行；但面板会点名说明「这一栏你的资料里还没有记录，需要你手动填写」，
而不是让它悄悄消失。工作经历和项目经历里同名的「描述」会结合各自分组识别，避免把工作内容填进项目描述。
点击面板中的字段名称即可跳到网页对应位置；缺资料时点「我来填写」会立即滚动到并聚焦网页控件，
直接在网页里输入或选择，提交或离开该控件后会自动重新扫描。四类字段结果都能单独折叠收起。
招聘页会按实习、校招、社招类型优先匹配相应经历：实习/校招强调实习经历与到岗时间，社招强调正式工作经历；
性质明确的相反类别不会互相顶替，工作台可逐段修改「经历性质」。类型不清楚或经历未标性质时保留待确认，不会悄悄串填。
经历性质会优先按简历区块标题与职位名称自动识别；简历也可以标记自己的「投递类型」（实习 / 校招 / 社招），
页面没有明确招聘类型时用它筛选经历，页面有明确类型时仍以页面为准。本地规则解析和模型解析都会读取原文中的
「求职类型 / 投递类型」以及经历性质标注，模型不会根据公司或行业猜测未写明的性质。
经历区块与招聘类型冲突时，面板会说明有资料但类别不匹配，并留给用户手动补充。

每个求职方向单独保存一份简历；新建方向后上传该方向自己的简历，不会复制其他方向的经历。网申和「岗位匹配 → 生成针对性建议」都会结合岗位名称、页面/粘贴的岗位描述和已分析的匹配岗位，在所有方向中自动选择相关度最高的简历；工作台当前选中项只影响编辑，岗位信息不足时才回退到当前档案，并在面板说明。岗位描述中写有「岗位名称 / 招聘职位」或职位标题时，工作台的岗位名称输入框会自动填入，手动填写的值不会被覆盖。

### 2. 填写策略

每个字段都按固定的信任层级求解候选值：

```
该网站的历史记忆 → 已确认的记忆 → 学到的记忆 → 简历资料 → 由简历整理生成 → 公开的默认值
```

每一条候选值都带**来源说明**和**简历原文引用**，显示在面板里。层级之外还能看到「为什么」——
这是产品的核心，而不是装饰：一个不能解释自己为什么这么填的自动填写工具不值得信任。

超过 400 字的开放题（自我介绍、职业规划）会从你的真实经历里组装一段草稿，并标注「由简历内容整理生成」。
资料不足时它返回空，而不是编一段听起来合理的话。

### 3. 自主学习

资料库里没有的字段，你自己填了之后会被记住：

- 只学习**扩展没有填过**的字段（按值比对，不依赖时序，避免把自己写进去的内容当成用户输入）
- 点「我来填写」会把焦点移到网页控件；用户在网页输入后，提交或离开字段会按学习设置保存记忆并重新识别
- 验证码、协议勾选框、密码字段永不记忆
- 敏感字段（身份证号、手机号、地址）照常存储，但在界面上默认打码
- 同一字段再次出现时，记住的值优先于简历

工作台里有完整的「记忆库」页面，可以逐条核对、修改、删除，或全部清空。

## 网页工作台

浏览器图标弹窗只负责当前页面，完整功能在工作台：

| 视图 | 做什么 |
|------|--------|
| **总览** | 「我现在该做什么」——按真实工作顺序排列的下一步 |
| **简历** | 上传 PDF/DOCX/TXT，默认先用 OCR 与结构化模型识别（扫描件、PNG/JPG 也可）；首次上传会明确提示哪些内容会离开设备；模型不可用时自动退回本机规则。逐字段核对解析结果并就地修改；按不同求职方向建立独立档案；解析器升级后可「重新解析」，先看差异再选择只补充空白或整体覆盖，并可撤销 |
| **岗位** | 粘贴岗位描述，提取要求与权重，生成针对性简历建议、求职信、面试准备 |
| **台账** | 每次投递的记录、阶段、下一步行动、面试前回顾当时提交了什么 |
| **记忆** | 查看、编辑、删除扩展学到的内容 |
| **设置** | 行为偏好、外观、导出/导入/删除全部数据、导出诊断日志 |

岗位润色遵循一条硬规则：**重排、强调、改写，绝不编造**。
每条改写后的经历都保留原文与改写理由，因为一份面试时讲不出来的简历比没润色过更糟。
缺口分析会如实告诉你哪些要求简历没有覆盖，而不是用漂亮话掩盖。

## 遇到问题时

Quill 把每一次扫描、生成方案和填写都记录在本机。遇到页面没识别对、字段没填上，直接带上现场：

- **网页上的填写面板**：点右上角「报告问题」，诊断信息会复制到剪贴板。
- **工作台**：设置 →「诊断与日志」，可以补充几句问题描述，然后导出 `quill-诊断-*.json` 发给开发者。

诊断文件包含页面结构（字段标签、识别键、置信度）、最近一次扫描/填写的结果和操作时间线；
**不包含**你填写的值、简历正文、密码、Cookie，URL 里的查询参数也会在记录前去掉。
记录只写入本机浏览器，最多保留 500 条 / 256 KB，不会自动上传——只有你亲手复制或导出时才会离开这台设备。

## 开发

```bash
npm install

npm run typecheck      # 三个包的 TypeScript 检查
npm test               # 177 个单元测试（解析、分类、策略、学习、润色、台账、诊断）
npm run build:extension  # 构建扩展（含工作台页面）→ extension/dist
npm run build:web        # 构建独立网页版 → web/dist

npm run dev:server     # 简历识别服务（需要 UNISOUND_API_KEY，见 server/README.md）

npm run browsers       # 下载 Chrome for Testing（e2e 需要）
npm run test:e2e       # 真实浏览器端到端验证（130 项断言）
npm run test:all       # 上面全部跑一遍
```

### 真实页面校准

端到端测试用的是我们自己写的表单，标签结构对扫描器天然友好。
要衡量它在真实网申页面上的表现，用探针扫描 `../测试html` 里的离线存档：

```bash
npm run probe                        # 逐页报告识别率与未归类字段
npm run probe -- 百度招聘.html        # 只测一页
npm run probe -- --dir ../测试html --json
```

探针会以禁用 JavaScript 的方式载入存档（避免页面脚本把保存下来的表单重渲染成登录页），
注入内容脚本里的同一份扫描器，输出每个字段的标签来源、归类键和置信度。
标为「未归类」的字段值得先看：它们通常意味着词典缺一个键，或者标签恢复在真实 DOM 里断了。

### 在浏览器里加载

1. `npm run build:extension`
2. Edge 打开 `edge://extensions`（Chrome 为 `chrome://extensions`），开启「开发者模式」
3. 「加载已解压的扩展程序」，选择 `extension/dist`
4. 点扩展图标 → 打开工作台 → 上传简历

> 修改代码后需要回到扩展页点一次「重新加载」，再刷新已打开的业务页面，
> 页面里才会运行新版本的内容脚本。面板标题旁会显示当前运行版本（例如 `v0.4.4`）。

### 为什么需要 Chrome for Testing

正式版 Google Chrome 会静默忽略 `--load-extension`（日志里写
`is not allowed in Google Chrome, ignoring`），并且阻止自动化标签页访问 `chrome-extension://`。
端到端测试因此必须用 Chrome for Testing，`npm run browsers` 会下载到 `chrome/`。

## 结构

```
packages/core       与环境无关的核心引擎（无 DOM、无 chrome API）
  text.ts           归一化、相似度、日期解析
  types.ts          领域模型
  fields/           字段词典 + 分类器
  resume/           简历分段与解析
  strategy/         取值求解、选项匹配、长文组装、学习
  tailor/           岗位分析与简历润色
  ledger/           投递台账的纯函数

packages/design     设计令牌与基础层（两个界面共用）

extension/          MV3 扩展
  src/content/      扫描、标签恢复、填写、学习监听
  src/ui/           面板、弹窗、设置、首次运行
  src/shared/       消息协议、存储
  build.mjs         打包脚本

web/                工作台（React + Vite）
  src/data/         存储适配器（扩展内 / localStorage 双后端）+ 识别服务客户端
  src/views/        六个视图

server/             简历识别服务（Node + 原生 fetch，平台密钥只在服务端）
  src/unisound.mjs  u2-ocr / u2-flash 客户端与草稿校验
  src/pdf.mjs       PDF 文字层重建 + 扫描页渲染
  src/extract.mjs   “文件 → 文字 → 结构化草稿”流水线

test/               单元测试 + 端到端 + 真实表单样本
scripts/            构建、打包、测试、图标生成、真实页面探针
```

核心引擎刻意不依赖 DOM 或 `chrome.*`，所以同一份逻辑同时跑在
service worker、内容脚本和网页工作台里，单元测试也不需要浏览器。

## 设计

苹果式材质语言，从 apple.com 实际发布的 CSS 里取值而非凭印象：

| 令牌 | 值 | 来源 |
|------|-----|------|
| 导航玻璃 | `saturate(180%) blur(20px)` | apple.com globalheader.css |
| 导航底色 | `rgba(250,250,252,.8)` / `rgba(22,22,23,.8)` | 同上 |
| 主色 | `#0071e3` / `#0077ed` / `#006edb` | `--sk-button-background` |
| 字体栈 | SF Pro Display/Text → PingFang SC → 微软雅黑 | apple.com font-family |
| 缓动 | `cubic-bezier(0.66,0,1,1)` 系 | product overview CSS |
| 描边 | `0.5px` 发丝线 | 同上 |

其余是自定的：9 级字号、4px 间距网格、圆角阶梯、语义色、阴影配方。
暗色不是反转——它按 Apple 的做法用表面明度建立层次，并降低强调色饱和度。

面板用 shadow root + `all: initial` 隔离，页面样式进不来，面板样式也出不去。
窄屏下面板变成底部抽屉，工作台的侧栏变成底部标签栏。

## 隐私

- 简历、记忆、台账默认全部在 `chrome.storage.local` / `localStorage`
- 简历文件不保存原文件，只保留提取出的文字（`storage.local` 约 10 MB 上限）
- 只有你点击「填写」时才会写入页面
- 验证码与协议勾选框永不自动填充
- 设置页可以一键导出 JSON 备份，或彻底删除

**模型识别的例外**：该功能默认关闭。你主动开启后，第一次上传简历前仍会停下来明确询问。只有你确认后，
这份简历的文字才会发到你的识别服务器，由 `u2-ocr` / `u2-flash` 转写并结构化。服务器不保存文件、
草稿或识别结果，也不把简历内容写进日志；平台密钥只存在于服务器的环境变量里，浏览器不接触。
保持关闭时，简历识别完全使用本机规则，不产生任何网络请求。

除此之外，唯一离开设备的情况是你主动点击「导出」。
